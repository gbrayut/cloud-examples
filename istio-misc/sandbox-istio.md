# OSS Istio on GKE Sandbox (Gvisor)

When using upstream Istio on GKE Sandbox (gvisor) node pools, Istio must be installed with the [CNI node agent](https://istio.io/latest/docs/setup/additional-setup/cni/#installing-with-helm) so that it injects the **istio-validation** init container (which does not require any pod privileges) instead of **istio-init**. Here are some general instructions:

```shell
# install istio with privileged istio-cni-node daemonset and unprivileged istio-validation initContainers
helm repo add istio https://blob.istio.io/istio-release/charts
helm repo update

helm install istio-base istio/base --version "1.32.0" -n istio-system \
  --create-namespace --set global.platform=gke --set defaultRevision=default
# If you get Error: INSTALLATION FAILED: ... CustomResourceDefinition ... exists
# then try adding this line to fix an issue where GKE sometimes already includes
# a copy of the networking.istio.io/v1 ServiceEntry CRD
  --set base.enableCRDTemplates=true --set 'base.excludedCRDs[0]=serviceentries.networking.istio.io'

helm install istio-cni istio/cni --version "1.32.0" -n istio-system \
  --wait --set global.platform=gke

helm install istiod istio/istiod --version "1.32.0" -n istio-system \
  --wait --set pilot.cni.enabled=true --set global.platform=gke

# check for istio-cni-node-.... pods on each node, and tail their logs if there are any issues
kubectl get pod -n istio-system -o wide

# apply test workload for gvisor
kubectl create ns test-istio
kubectl label namespace test-istio istio-injection=enabled
kubectl apply -f https://github.com/gbrayut/cloud-examples/raw/refs/heads/main/istio-misc/sandbox-istio-gvisor.yaml

kubectl get pod -n test-istio -o wide
```

# OSS Istio on GKE Agent Sandbox (Gvisor)

If you are using [GKE Agent Sandbox](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/machine-learning/agent-sandbox) there are some additional settings you will need to configure before Istio sidecars will work. Specifically the built-in `networkPolicyManagement: Managed` settings have a [default-deny posture](https://github.com/kubernetes-sigs/agent-sandbox/tree/main/examples/policy/network-policy-management) that will block kube-dns and istiod access. So for istio-proxy sidecar to be able to start inside the Agent Sandbox you will need to enable `dnsPolicy: ClusterFirst` and configure egress rules for DNS and istiod. See [sandbox-agent-istio-warmpool.yaml](./sandbox-agent-istio-warmpool.yaml) for an example **SandboxTemplate**, **SandboxWarmPool**, and **SandboxClaim** with settings that should work for Istio sidecars:

```shell
# apply Agent Sandbox example that works with istio sidecars
kubectl apply -f https://github.com/gbrayut/cloud-examples/raw/refs/heads/main/istio-misc/sandbox-agent-istio-warmpool.yaml

# check pods and network policy generated by template
kubectl get networkpolicy,pods -n test-istio

# if pod remains stuck at Init:1/2 check istio-proxy logs
kubectl logs -n test-istio agentsandbox-warmpool-<tab> -c istio-proxy
```

# OSS Istio on GKE Sandbox (Microvm)

If the GKE cluster is also using kata containers (microvm), those cannot use CNI based init and instead must have the in-pod privileged istio-init. You can [manually inject](https://istio.io/latest/docs/setup/additional-setup/sidecar-injection/#manual-sidecar-injection) the containers or use a customized injection template. See **sidecarInjectorWebhook.templates.kata-init** section in [sandbox-istiod-values.yaml](./sandbox-istiod-values.yaml) and **inject.istio.io/templates** annotation in [sandbox-istio-microvm.yaml](./sandbox-istio-microvm.yaml):

```shell
# update istiod to include a kata-init injector that uses istio-init
helm upgrade istiod istio/istiod -n istio-system --version "1.32.0" \
  --wait -f https://github.com/gbrayut/cloud-examples/raw/refs/heads/main/istio-misc/sandbox-istiod-values.yaml

# deploy microvm sandbox with inject.istio.io/templates annotation
kubectl apply -f https://github.com/gbrayut/cloud-examples/raw/refs/heads/main/istio-misc/sandbox-istio-microvm.yaml

kubectl get pod -n test-istio -o wide
```

For an Agent Sandbox example see [sandbox-agent-istio-microvm.yaml](./sandbox-agent-istio-microvm.yaml)
